# Parks hosted payment contract

First adapter: Stripe hosted Checkout, optional city account configuration; offline payments remain usable. No card details enter Townlight. Official contracts checked November 24, 2026: https://docs.stripe.com/api/checkout/sessions/create https://docs.stripe.com/api/checkout/sessions/retrieve https://docs.stripe.com/api/refunds/create .

Host makes outbound authenticated HTTPS only, with durable intent IDs as Stripe Idempotency-Key. Resident return URLs are not payment evidence. The unattended host polls its stored session IDs, retrieves authoritative Stripe session data, verifies exact intent/obligation metadata, currency, amount, paid status and payment_intent, then records the actual ledger payment. This fits the existing public portal inbox/acknowledgement bridge without exposing private Windows services or requiring another inbound webhook deployment.

payment_intents table: id UUID PK; obligation_id FK; command_key unique <=255; request JSON (exact provider request amount_cents/currency/success_url/cancel_url/metadata, no secrets); amount_cents positive; currency; state prepared/open/paid/expired/failed; provider_session_id nullable unique; checkout_url nullable; provider_payment_id nullable; last_error nullable; created_at/updated_at. Reserve canonical balance with obligation FOR UPDATE; only one prepared/open intent per obligation via owning lock. Durable prepared survives timeout. Retry reuses exact saved request and intent ID, never invents new charge. Offline payments and refunds must not modify a balance reserved by a prepared/open intent. Explicit provider expiry/retrieval is required to release reservation; local timeout alone is insufficient. Paid/expired are final, do not silently revive.

refund_intents table: id UUID PK; payment_ledger_id FK ledger; obligation_id FK; command_key unique; amount_cents positive; reason bounded; state prepared/pending/succeeded/failed; provider_refund_id nullable unique; last_error nullable; created_at/updated_at. Validate actual Stripe payment ledger; reserve refund amount against sum succeeded+prepared+pending intents for that payment. Persist prepared before network. Stripe create refund uses actual payment_intent, explicit amount, idempotency UUID. Record ledger refund only when retrieved response status succeeded and amount/currency/payment_intent match. Pending remains pending, shown as such. Failed is explicit. Replay cannot duplicate refund.

Transport accepts configured secret only constructor, never returns/logs it; fixed https://api.stripe.com/v1 API origin with redirects disabled/timeout. Calls create_checkout, retrieve_checkout, create_refund, retrieve_refund. Return strict bounded JSON. Currency USD first supported online (offline currency unchanged) so integer cents are unambiguous; city configuration and UI disclose supported online currency. All state and actual receipts survive host restart.
